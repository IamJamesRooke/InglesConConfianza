# Kickoff prompt for the curriculum-collation session (2026-09-15)

Paste into a fresh session. Written to start with discussion, not action.

> You are a curriculum architect helping me — a teacher building "Inglés con Confianza", an English course for Spanish-speaking adults in Bogotá, taught in a Michel Thomas style: build long sentences from a few verb pieces, short explanation → immediate retrieval, no memorisation. Repo: /data/MEGA/Projects/InglesConConfianza. Read first: AGENTS.md (curriculum boundaries — PostgreSQL is the canonical store, curate via reviewed TSV manifests, never delete outright, don't add tables), docs/curriculum-database.md, docs/teaching-methodology.md, docs/curation/collation-brief.md (a first attempt — a draft, not a decision), and my two real lessons in web/data/lessons.json.
>
> THE PROBLEM. ~4,250 concepts with collections as facet:value tags and a P1–P5 priority enum (all Unranked). I want the database to tell an AI — and me — what to teach in which order. Priority is the wrong idea: it's about LAYERS, like an onion — outer layers depend on inner ones ("I want something" → "I want to do something" → only after object pronouns, "I want you to do something"). I know intuitively which of two concepts comes first but can't eyeball 4,000 and can't yet state the rule. Also: coverage matters more than completeness — each grammar pattern must be taught at least once (phrasal verbs: "look for" vs "look at" is enough; cognates: importante → important unlocks thousands) — and I'm not confident in my taxonomy (topic → family → group), which was built for browsing.
>
> A previous session proposed: layers as sentence frames in teaching order (~15–20); each concept at the first frame that needs it; structural concepts (~200–400) placed by hand with AI proposals, vocabulary by rule; 3–5 exemplars per pattern-family, the rest long tail (core / supplementary / reference); stored as `stage:`/`role:` facets, no schema change; taxonomy measured against layers, not rebuilt. Still too vague to act on.
>
> IN ORDER: (1) Discuss, don't build — ask me concrete either/or questions from the database until you can state my ordering rule in my words. (2) Propose the model on one page with trade-offs; I approve. (3) Only then plan execution: batches, model routing (I'm on a limited budget), spot-checks, and what the lesson builder reads from the result. Constraints: no DB writes until I say so; no new tables; no deletions; not concurrent with my edits; leave web/src alone (another session owns the builder).
