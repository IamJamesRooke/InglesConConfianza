# Assets: where they live, and cleaning up after yourself

Two kinds of generated/uploaded file live under `web/public/`, both
content-addressed (the filename is derived from the content, or from the
text being spoken), which means **every edit leaves the old file behind** —
nothing is ever overwritten in place, only added to.

## Audio (`web/public/audio/`)

- `us-man/<sha1(text)>.mp3`, `uk-woman/<sha1(text)>.mp3` — one clip per
  (speaker, spoken English text) pair: a tested piece's first accepted
  answer, or an ordinary sentence slide's full joined English.
- `explanations/<sha1(markdown source)>.mp3` — the two-voice explanation
  narration, keyed by the authored markdown itself.
- `instructions/<sha1(trimmed text)>.mp3` — a sentence/vocabulary slide's
  spoken instruction line.
- `manifest.json` — `{ "<hash>": ["us-man", "uk-woman"], "explanations": {
  "<hash>": true }, "instructions": { "<hash>": true } }`, read by the
  learner side to know which clips exist.

Generated by `npm run audio:generate` (`web/scripts/generate-audio.ts` →
`web/src/lib/audio/generate-clips.ts`), which needs `GOOGLE_TTS_API_KEY` —
without it, the script prints what it would generate and exits 0. **Every
audio clip is regenerable**: delete one (or all of them) and
`audio:generate` reproduces it from `data/lessons.json` alone.

`web/public/speakers/` (the avatar SVGs/portraits) is a **different**
directory, hand-authored, never touched by generation or by
`assets:prune` — see docs/design/speech.md "Avatars".

## Images (`web/public/lesson-media/`)

An explanation slide's optional image (docs/design/onboarding.md "media
option", docs/design/lesson-builder.md "Explanation images"). Uploaded
through `POST /api/admin/lesson-builder/media`
(`web/src/app/api/admin/lesson-builder/media/route.ts`), named
`<slug-of-alt-or-"imagen">-<first 10 hex of sha1(content)>.<ext>` — pasting
or picking the identical bytes twice reuses the same file; editing the
image (a new upload) always adds a new file rather than overwriting the
old one, even when the old one is no longer referenced anywhere.

**Images are not regenerable** — unlike audio, there is no `data/` source
to rebuild one from. If one is ever deleted by mistake, it's recoverable
from git history (committed like any other file, small, not gitignored)
but not from `data/lessons.json`.

## Why cleanup is a separate step

Because nothing is ever overwritten, `web/public/audio/` and
`web/public/lesson-media/` only grow: renaming a piece's English answer,
editing an explanation's wording, or replacing an image all leave the
previous file — now unreferenced by any lesson — sitting on disk forever
unless something removes it.

## `npm run assets:prune`

`web/scripts/prune-assets.ts`, with its pure analysis in
`web/src/lib/assets/referenced-assets.ts` (no fs access there, so it's
plain unit-tested — `web/tests/unit/referenced-assets.test.ts`).

- **Referenced audio** = exactly the clip set
  `web/src/lib/audio/generate-clips.ts`'s `listWantedClips` would generate
  for the *current* `data/lessons.json`, across every speaker, plus every
  hash `manifest.json` still lists as wanted for the same reason
  (deduplicated, drafts included). Reuses the generator's own hash
  derivation — it never re-derives a sha1 itself, so the two can't drift
  apart.
- **Referenced images** = every `ExplanationBlock.image.file` across every
  lesson.
- **Draft modules and draft lessons count as references** — the owner may
  be mid-edit, and a draft lesson's audio/images shouldn't be swept away
  out from under them.

Default is a **dry run**: prints how many clips/images are referenced,
lists every orphan file with its size and the total reclaimable, lists any
*missing* asset (referenced but not on disk — for audio this just means
"run `npm run audio:generate`"; for images it's printed as an error line,
since there's nothing to regenerate it from), and reports how many stale
`manifest.json` entries would be pruned.

`--apply` deletes the orphan files and rewrites `manifest.json` with the
stale entries removed. It refuses to run at all if `data/lessons.json`
fails to parse, or parses to zero lessons — either looks like a broken
read rather than a genuinely empty course, and deleting "orphans" against
that data would be unsafe.

Scope, strictly: `public/audio/**/*.mp3`, `public/audio/manifest.json`, and
`public/lesson-media/*`. Never `public/speakers/`, never anything else.

**Run it before a deploy** (dry run first, read the summary, `--apply` when
it looks right) — a leaner `public/` means a smaller deploy and a shorter
`git status` to review.
